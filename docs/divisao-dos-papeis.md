# 1. Como a equipe se organizou

O grupo é formado por cinco integrantes, e a divisão de papéis foi feita com base nas áreas que cada um pretende seguir na carreira, permitindo que todos 
ganhassem experiência prática na função de seu interesse, em vez de distribuir os papéis de forma aleatória.

# 2. Processo de decisão

Antes da divisão final, foi elaborado duas propostas de distribuição de papéis

| Opção A  | Opção B |
|----------|---------|
| Back-end | Back-end e DevOps|
| Front-end | QA, suporte ao usuário e acessibilidade |
| Banco de dados | Banco de dados |
| Segurança da informação | Segurança da informação |
| Back-end | Full Stack |

cada uma priorizando de forma diferente os interesses individuais informados por cada integrante. As duas propostas foram discutidas em reunião, e a equipe optou 
por seguir a proposta da opção A, com a retirada de um back end e adição de uma pessoa responsável pelo QA e acessibilidade.

# 3. Forma de trabalho

A documentação do projeto foi organizada em um repositório no GitHub, com uma pasta central de documentação (docs) reunindo os textos gerais e os escopos de cada função, e pastas específicas 
para o material técnico de apoio de cada área.
